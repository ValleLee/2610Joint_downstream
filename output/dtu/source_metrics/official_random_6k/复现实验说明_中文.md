# DNGaussian 与 DropoutGS 官方 DTU 随机初始化复跑

状态：已完成。DNGaussian、DropoutGS 各 15 个场景全部训练至 6000 步，所有正式归档和统一 mask 指标评测通过；全程使用 0–5、7 号卡，未使用 6 号卡。汇总见 [结果总结与分析](结果总结与分析_中文.md)，逐场景指标见 `metrics/`。

## 官方设置核对

- 代码来自本机官方仓库：DNGaussian `Fictionarry/DNGaussian` 与 DropoutGS `xuyx55/DropoutGS`；每次训练记录 commit、关键源码 SHA-256、实际参数和日志。
- 本轮代码版本：DNGaussian `22a588c74db48e587294451005a05b156435b3d2`；DropoutGS `5ff8d1ae469970f924de4eca8d3498333d6f3214`。DNGaussian 配套光栅器依赖为先前 LLFF 复现已使用的 Ashawkey `diff-gaussian-rasterization` commit `8829d14f814fccdaf840b7b0f3021a616583c0a1`；DropoutGS 使用其代码目录内的旧接口光栅器源码。源码归档在本目录 `code/`。
- 两个官方 `train_dtu.py` 入口均采用 `--n_sparse 3 --rand_pcd --iterations 6000 -r 4`。reader 按 CoR-GS DTU 划分仅选 `rect_023/026/029` 三张 RGB 做训练，测试集合严格为官方 split 的 25 个视角。
- 随机种子在两仓库 `safe_state()` 中固定为 0，包含 Python、NumPy 和 PyTorch。DTU 官方脚本里的随机初始化是 1000 个随机点；它不是 MVS 初始化。采样盒坐标范围从 DTU `sparse/0/points3D.bin` 的 49 相机 COLMAP 稀疏模型估计，因此只能称为“三张训练 RGB”，不能称为全部几何信息严格只来自三视角。训练损失只从三张训练 RGB 和相应 DPT 深度读取监督。
- 参数逐项沿用仓库 `scripts/run_dtu.sh` / `scripts/train_dtu.sh`：`lambda_dssim=0.6`、DTU densification/pruning 参数、`test_iterations=100,1000,2000,3000,4500,6000`、`save_iterations=100,500,1000,3000,6000`。DropoutGS 另加官方 dropout 参数 `rate=0.3`、`consistency_lambda=0.5`、`edge_threshold=0.001`、`size_threshold_rate=1`。
- 评测使用 CoR-GS 源码定义的 25 张测试 RGB、对应 25 张 mask 和项目 canonical GT。官方 mask 文件编号为 0-based，渲染相机编号 `rect_NNN` 为 1-based；评测程序按 `mask=(NNN-1)` 明确配对，不按目录顺序猜配对。
- scan8 已确认两方法初始化随机点云哈希一致（`5a5f1780abf219966efac836e6e00fc14bc3b498cd96e42874912eef4d84135f`），各自生成 25 张命名测试渲染且通过对应检查。CoR-GS mask 指标为：DNGaussian **19.7849 / 0.8037 / 0.2001**，DropoutGS **20.5619 / 0.8356 / 0.2119**（PSNR / SSIM / LPIPS）。这是单场景预跑，不代表 15 场景汇总。

## 唯一兼容性适配

DNGaussian README 要求用 DPT-Large 生成 DTU 单目深度图，官方生成器把逐图 min-max 归一化结果写成 16-bit PNG；但两个仓库的 `PILtoTorch()` 直接执行 `torch.from_numpy(np.array(image))`，当前 PyTorch 不支持 `uint16`，原始官方入口会在第一步训练前崩溃。此次不改训练损失或优化代码，而是在 `/tmp` 中为运行数据生成 loader 可读的 8-bit 深度图：`round(uint16 * 255 / 65535)`。它保留官方逐图归一化的 0–1 深度范围，只降低量化位数；原始深度文件保留不动。转换清单记录 49 张输入/输出哈希。此做法与本仓库已完成的 DNGaussian LLFF 16→8-bit loader 兼容处理相同。

两仓库附带的光栅器代码按各自 Python/CUDA 版本在 `/tmp` 单独编译并优先加载。预检曾先误加载环境中另一套带 `antialiasing` 参数的 Graphdeco 扩展，因接口不兼容在第 0 步终止；改用仓库配套扩展后，scan8 两方法均已跑满 6000 步。失败的预检不计入实验，也未写入结果目录。

## 临时文件与归档

模型、优化器 checkpoint、迭代点云和渲染缓存放在 `/tmp/lilinwei/1007fsgsmvs_dtu/official_random_6k`。每个场景成功完成 6000 步和渲染后，才将最终 checkpoint gzip、初始化随机点、最终点云、25 张命名渲染、参数、日志和 manifest 保存到本目录对应方法/场景下；归档计数/校验通过后删除该场景临时模型目录。若 `/tmp` 接近满载，先清理已成功归档的中间 checkpoint/cache；保留当前运行模型和日志。GPU 6 不使用。

## 解释边界

这批结果回答“按各自官方 DTU 随机初始化实现时的表现”，不与共用三视角 MVS PLY 的主表混为同一初始化对照。随机点生成范围依赖全 49 相机稀疏模型；如果目标是全几何先验也严格限于三视角，需要另做改写初始化的消融，不能称作官方默认复现。
